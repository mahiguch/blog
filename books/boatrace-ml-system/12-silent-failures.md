## この章で学ぶこと

| 観点 | 内容 |
| --- | --- |
| ML | 学習母数が知らないうちに減っていた事故、古い係数で静かに壊れることを防ぐ |
| システム | エラーにならない失敗の型、観測可能な不変条件を置く、学習と推論の分離、依存順序の明示 |

## 1. cone の外に書いたファイルは消える

- sparse-checkout の cone 外に書いたファイルは `git add` に無視され、エラーにならずに消える
- `data/estimate/{suji,kimarite}/tables/` は導入時から永続化されておらず、`logloss.csv` は一度もリポジトリに存在しなかった(2026-08-22 修正)
- 逆に、cone 外パスが 1 つ混ざると `git add` 全体が落ち、その回のコミットが丸ごと消える

## 2. 学習母数が cone の広さで決まっていた

- `build_kimarite.py` は「全履歴で学習」と書いてあるのに、race_cards が cone に無い日を無言でスキップしていた
- 実際の母数は直近 8 か月(43,595 → 30,160 レース、31% 欠落)、しかも毎月 1 か月ずつ拡大していた
- 検知: ジョブログの `races=NNNNN (開始日〜終了日)` の左端が `data/results/realtime/` の最古日と一致するか、という不変条件

## 3. 学習と推論を分ける

- 学習は sklearn、推論は係数 CSV から softmax を直接計算。2 分毎のバッチはモデルを読み込まない
- 係数のクラス構成が `CELLS` とズレていたら**黙って動かず落ちる**。古い係数で静かに壊れるのを防ぐ

## 4. 依存順序を壊さない

- `build_index` → `build_kimarite_probs` → `build_kimarite_picks` の順序を崩すと買い目が 0 行になる
- 前提ファイルが無いときは「作り方を示すメッセージ付きで落ちる」(素の FileNotFoundError にしない)

## 5. 失敗の型を分類する

| 型 | 例 | 対策 |
| --- | --- | --- |
| 書いたのに消える | cone 外の git add | 出力パスを cone に入れるテスト |
| 減っているのに動く | 学習母数 31% 欠落 | ログに範囲を出し、不変条件で検知 |
| 古いまま動く | 係数のクラス不一致 | 構成が一致しなければ落とす |
| 片方だけ取れる | 結果と払戻 | 独立 append で次サイクル補完 |
