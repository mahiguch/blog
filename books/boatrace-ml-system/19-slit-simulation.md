## この章で学ぶこと

| 観点 | 内容 |
| --- | --- |
| ML | 事後には最強の特徴量が事前には使えないこと、必要精度の逆算(MAE と回収可能利得)、モンテカルロの落とし穴(共通ショック・裾の厚さ)、予測区間の校正(Student-t)、撤退ラインを実験の前に設計する手順 |
| システム | Phase 0 の校正が通らなければ実装しない、縮退版(ST 帯)だけを出荷する、再挑戦条件を数値でドキュメントに残す、既存の予想者に一切影響させない分離 |

第 18 章で作った AI 推定 ST は、スタート予想図の見た目を良くしましたが、買い目には効きませんでした(v5_slit は control と有意差なし)。この章はその続きです。「スリット隊形さえ分かれば展開が読める」という定説を実測 ST で検証し、それが事前には組めないことを数値で確認し、分布で出す計画(slit_sim)を立て、事前に決めた撤退ラインに沿って縮退し、最終的に「ST の予測区間を帯で描く」だけを出荷するまでの記録です。

この章の主役はモデルではなく、**実験の前に「どこまで落ちたら何を出すか」を決めておく**という手順です。

## 1. 定説「スリットで決まる」は正しい

### 1.1 スリットを数値にする

ボートレースの「スリット」とは、スタートライン通過時の 6 艇の前後関係です。`data/results/realtime/` の `Nコース_スタートタイミング`(以下 ST)は大時計 0 秒からの遅れ秒なので、これを距離に換算すれば隊形になります。設計書 `docs/design/slit_tenkai.md` ではスタート艇速を約 50km/h = 13.9 m/s と置き、ST 差 0.01 秒 ≒ 0.14 m、艇長 3 m の 1 艇身 ≒ ST 差 0.216 秒としています。

```
lead[c]   = (mean(ST) - ST[c]) * 13.9     # 正 = レース平均より前
gap_in[c] = lead[c] - lead[c-1]           # 正 = 内隣艇より前(まくり圏)
in_margin = lead[1] - max(lead[2..6])     # 正 = 1 コースがスリット先頭
spread    = (max(ST) - min(ST)) * 13.9    # スリットの縦の伸び
```

`in_margin` が「1 コースが外の最先行艇よりどれだけ前に出ているか」で、この章を通じて最も重要な量です。

:::message
第 15 章のスタート予想図は 1 艇身 = 0.135 秒(スリット付近 80km/h 換算)で描いています。この章の分析(slit_tenkai.md)は 13.9 m/s = 0.216 秒/艇身で統一されており、換算係数が違います。どちらも「ST 差 × 艇速」の同じ式で、艇速の仮定だけが異なります。本文の m 表記はすべて 13.9 m/s 換算です。
:::

### 1.2 隊形が分かれば決着はほぼ決まる

2025-11-01〜2026-08-09 の 41,776 レース(6 艇の ST が揃い、1 着艇が進入コースに紐付いたもの)を `in_margin` と先行勢の位置で 6 分類した結果です(2026 年 8 月時点)。

| 隊形 | 占有 | 逃げ | まくり系 | 1 着 = 1C |
| --- | ---: | ---: | ---: | ---: |
| ほぼ揃い(±0.6m) | 56.7% | 64.0% | 17.8% | 66.4% |
| イン半艇身遅れ / センター先行 | 17.9% | 36.1% | 40.7% | 39.0% |
| イン半艇身遅れ / 外(5-6)先行 | 12.5% | 45.6% | 36.5% | 48.1% |
| イン明確先手(+0.6m 以上) | 5.4% | 71.9% | 12.1% | 73.2% |
| イン大幅遅れ / 外(5-6)先行 | 3.9% | 18.9% | 64.0% | 20.9% |
| イン大幅遅れ / センター先行 | 3.7% | 8.0% | 70.9% | **9.5%** |

「イン大幅遅れ / センター先行」では 1 コースの 1 着率が **9.5%** まで落ちます。全体では 55.7% ですから、6 分の 1 以下です。逆に「イン明確先手」なら逃げが 72% です。`in_margin` を連続量で見ると、−1.25〜−0.6m で 47.9%、−2.0〜−1.25m で 30.5% と、**1.2m(ST 差 0.09 秒)の遅れで 1 コースの勝率が半分**になり、+0.6m を超えると 73% 前後で飽和します。非対称なので線形特徴量では表現できない形です。

### 1.3 モデルに入れると他のどの特徴量より大きい

目的変数を 1 着コース(6 クラス)、時系列 split(前 80% 学習 / 後 20% 検証)、HistGradientBoosting で log loss を測った結果です。

| 特徴量 | log loss | 1 着的中率 |
| --- | ---: | ---: |
| コース事前確率のみ(ベースライン) | 1.3423 | 55.1% |
| 全国平均 ST から組んだスリット | 1.2805 | 55.2% |
| スタート展示 ST から組んだスリット | 1.3373 | 55.1% |
| **実測 ST から組んだスリット(上限)** | **1.1703** | **58.7%** |

第 7 章の `強さpt`(v1_basic)に足した場合(結合できた 14,736 レース)は、`強さpt` 単独の 1.2725 から 1.1291 へ、**log loss −0.143** です。このリポジトリの他のどの特徴量(第 5 章のモーター指数、第 4 章の展示など)よりも大きな改善幅で、定説は数値の上でも正しいと言えます。

## 2. しかし事前には組めない

問題は、この表の「実測 ST」がレースが終わってから分かる量だということです。締切前に手に入る ST は 2 つしかありません。

| コース | corr(展示 ST, 実測) | MAE(展示) | corr(全国平均 ST, 実測) | MAE(全国平均) |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.048 | 0.114 | 0.209 | 0.053 |
| 4 | 0.053 | 0.119 | 0.250 | 0.053 |
| 6 | 0.059 | 0.136 | 0.216 | 0.060 |

スタート展示 ST は本番 ST との相関が **0.05** しかありません(平均も展示 0.074 秒 / 本番 0.158 秒と 0.08 秒ずれています)。全国平均 ST でも 0.21〜0.25 です。スリット隊形として見ると、先頭コースの的中率は展示 ST で 21.2%、全国平均 ST で 28.9%。**先頭コースすら 7 割外す**のです。

### 2.1 回収できるのは上限利得の 12%

§1.3 の `強さpt` への上積みで比べると、全国平均 ST スリットの改善は −0.018、実測 ST スリットの改善は −0.143 です。つまり事前に取れる情報で回収できるのは **0.018 / 0.143 = 12%** で、残り 88% は「当日どうスタートが揃うか」という締切前には存在しない情報です。

### 2.2 必要精度の逆算: MAE 0.016 秒

では ST 推定をどこまで良くすれば元が取れるのでしょうか。設計書では、実測 ST に正規ノイズ N(0, σ) を乗せた「疑似予測 ST」でスリットを組み直し、利得がどれだけ残るかを測っています(利得率 = 実測スリット利得を 100% とした割合)。

| σ | ST の MAE | 順位 Spearman | 先頭的中 | 利得率 |
| ---: | ---: | ---: | ---: | ---: |
| 0.000 | 0.000 | 1.000 | 100% | 100% |
| 0.010 | 0.008 | 0.914 | 79.9% | 95% |
| 0.020 | **0.016** | 0.817 | 67.5% | **75%** |
| 0.040 | 0.032 | 0.636 | 49.1% | 49% |
| 0.060 | 0.048 | 0.509 | 40.5% | 32% |
| 0.100 | 0.080 | 0.354 | 31.6% | 15% |

利得の 75% を取るには **MAE ≦ 0.016 秒**が必要です。現行(全国平均 ST)は 0.053 秒、第 18 章の M3 でも 0.0505 秒ですから、3 倍以上の改善が要ります。実測 ST のコース内標準偏差は 0.070 秒なので、MAE 0.016 は**分散の 95% を説明する**ことと同義です。選手が当日どこまで踏み込むかは事前情報に存在しないため、この水準は原理的に届かないと結論しています。

:::message
この逆算は「改善の努力を始める前に、必要な精度を数字で出す」ための手法です。第 9 章の検出力の逆算と同じ発想で、「もっと精度を上げれば効くはず」という期待を、実験の前に潰すか裏付けるかできます。ここでは潰れました。第 18 章で ST 推定の採用基準「MAE −10%」を撤回したのも、同じ結論の別の側面です。
:::

### 2.3 ST 分散の 56% はレース共通ショック

もう 1 つ、事前予測を難しくしている構造があります。実測 ST の分散を「レース平均(共通成分)」と「レース内偏差(個別成分)」に分解すると次のようになります(プロトタイプ、2025-11〜2026-08 の 36,767 レース)。

| 分解 | sd | 分散比 |
| --- | ---: | ---: |
| 実測 ST(周辺) | 0.0721 | 100% |
| レース平均 ST(風・水面・場全体の緩急) | 0.0539 | **55.9%** |
| レース内偏差(個別成分) | 0.0479 | 44.1% |

ST 分散の **56% はレース共通ショック**、つまり「そのレース全体が早かったか遅かったか」です。隊形はレース内の相対位置なので、共通成分は完全にキャンセルされ、隊形の予測には何も寄与しません。一方で、選手別の ST 標準偏差を素朴に測ると共通成分込みの 0.067 秒程度になり、これをそのまま隊形のサンプリングに使うと隊形が散らばりすぎます。

## 3. モンテカルロで隊形を分布として出す(slit_sim)

点推定のスリットを 1 本描いて「この隊形になる」と断定する路線は、§2 のとおり 7 割外します。そこで設計書 `docs/design/slit_sim_plan.md` は、**推定 ST に分散を持たせてサンプリングし、隊形と決まり手を確率として出す**計画を立てました。

- 目的: スタート予想図と展開説明の**誠実化**。「たぶんこの隊形」ではなく「ほぼ揃い 57% / イン遅れ 24% / イン先手 19%」と出す
- 非目的: 回収率の改善。§2.1 のとおり上積みは 0.018 が上限に近く、独立スロットを立てて A/B する価値がない。既存 predictor の `component_keys` には**一切触らない**(第 10 章のレジストリと分離する)

### 3.1 事前に判明していた落とし穴

計画の §0 には、プロトタイプで確認済みの落とし穴が「Phase 1 に入る前に織り込むこと」として列挙されています。素朴な実装は必ずミスキャリブレーションする、という警告です。

1. **σ には周辺 sd ではなくレース内残差 sd を使う**(§2.3)。周辺 sd 0.067 ではなく ≈0.047
2. **コース別 ST オフセットを入れないと隊形が偏る**。実測のコース別平均 ST は 1C 0.151 / 6C 0.181 と 0.030 秒(0.42m)の系統差がある。全国平均 ST はコース非依存なので、これを μ に使うと `in_margin` の平均が実測 −0.497m に対し MC −0.754m と 0.25m ずれ、「ほぼ揃い」が実測 56.7% に対し 38.5% しか出ない
3. **予測偏差には収縮が必要**。予測 ST のレース内偏差と実測偏差の相関は 0.241、回帰係数 β = 0.586。そのまま使うと自信過剰になる
4. **レース内偏差は裾が極端に厚い**。超過尖度 **26.1**。分位で見ると 50% 点は正規より内側(0.0283 vs 0.0328)、99% 点は外側(0.1450 vs 0.1252)で、芯は鋭く裾は重い。Student-t(df ≈ 5.9)がよく当てはまるが、プロトタイプでは t 化しても隊形の周辺分布はほとんど改善しなかった(2 のコースオフセット欠落が支配的)
5. **選手別 σ は実在する**。30 走以上の 1,544 選手を期間で半分に割った split-half で、sd の前半 vs 後半の相関は 0.555(平均 ST の 0.782 に次ぐ)。最安定五分位 0.0576 / 最不安定五分位 0.0762 と 32% の差がある

超過尖度 26.1 という数字は、正規分布(超過尖度 0)からどれだけ離れているかを表します。大出遅れのような裾の事象が、正規分布が想定するよりはるかに多いということです。

### 3.2 Phase 構成と受け入れ基準

計画は 4 つの Phase に分かれ、**Phase 0 は notebook での校正だけ**です。

| Phase | 内容 | 目安 | 前提 |
| --- | --- | ---: | --- |
| 0 | 校正パラメータ確定(notebook) | 2〜3 日 | — |
| 1 | boatracecsv: σ 推定 + MC + CSV + バッチ + docs | 3〜4 日 | Phase 0 合格 |
| 2 | fun-site: 取り込み + 型 + 描画 + テスト | 3〜4 日 | Phase 1 の CSV |
| 3 | 校正モニタ整備 | 1 日 | Phase 2 |

Phase 0 の受け入れ基準は 4 つで、学習窓 2026-03-01〜06-20 / テスト窓 2026-06-21 以降(第 18 章の `racer_st.py` Phase 2 と同一窓。μ を供給する推定 ST の定数がこの窓で凍結されているため、σ と β を別窓で引くと残差構造がずれる)で判定します。

1. `in_margin` の mean / sd / `|·| ≦ 0.6m` 率が実測と ±0.05m / ±0.05 / ±3pt 以内
2. 隊形 6 分類の周辺確率が実測出現率と各 ±3pt 以内
3. 決まり手 3 値の五分位校正で、各ビンの予測平均と実測が ±5pt 以内
4. 隊形確率の Brier score が「全レース一律に周辺分布を出す」定数予測を下回る

> 1〜3 が通らない限り Phase 1 に進まない。校正が取れていない確率を UI に出すのは、点推定スリットより悪い(数字がついている分だけ信用されてしまう)。

### 3.3 撤退ラインを先に決める

ここがこの章で最も強調したい点です。計画の §6 には、**Phase 0 を実行する前に**、基準が通らなかった場合の縮退順序が書かれています。

1. **隊形 6 分類 → 3 分類に粗くする**(イン先手 / 揃い / イン遅れ)。分類が粗いほど校正は取りやすい
2. **決まり手確率をやめ、隊形確率だけ出す**。決まり手は隊形テーブル経由の二段推論なので誤差が乗りやすい
3. **確率をやめ、ST 帯(p25〜p75)の描画だけ実装する**。§2.3 の分散分解が正しければ帯の幅は素直に出る。これだけでも「点推定スリットは 7 割外す」問題への回答にはなっており、Phase 1 の σ 推定と Phase 2 の描画前半だけで到達できる。3 まで落ちるなら実装規模は約 1/3(2〜3 日)

なぜ先に決めるのでしょうか。実験の後に「どこまでなら出せるか」を考えると、投じた工数を回収したい気持ちが判断に混ざり、校正の甘い確率を「参考値」などと言い訳をつけて出してしまいがちです。撤退の順序と、各段で満たすべき基準を先に文章にしておけば、結果が出た後は機械的に照合するだけで済みます。加えて、撤退ラインがあることで Phase 0 に 2〜3 日を投じる判断そのものが軽くなります。「全滅しても帯は出せる」と分かっているからです。

## 4. Phase 0 で不合格

`notebooks/slit_sim/report.md`(2026-08-10)が Phase 0 の判定記録です。パネルは 252,920 艇走 / 42,228 レース(うち 6 艇立ては学習 15,893・テスト 7,803 レース)、すべて因果的(各レースの μ / σ はそのレース日より前の実測 ST のみから作る)です。

### 4.1 本命案: 4 基準すべて FAIL

推定した定数は `BETA = 0.758`、`SIGMA_BY_COURSE = {1C 0.048 … 6C 0.053}`、Student-t(df 6.03)などで、§3.1 の落とし穴はすべて織り込んだ状態です。それでも、

| 基準 | 結果 | 判定 |
| --- | --- | --- |
| 1. `in_margin` 分布 | mean 実測 −0.513 / MC −0.629、`\|·\| ≦ 0.6m` 実測 55.6% / MC 44.7% | FAIL |
| 2. 隊形の周辺確率 | 「半艇身遅れ / センター」で +6.5pt 乖離(基準 ±3pt) | FAIL |
| 3. 決まり手の五分位校正 | 逃げ 11.0pt 乖離(基準 ±5pt) | FAIL |
| 4. 隊形 Brier | MC 0.6402 vs 定数予測 **0.6343** — 定数に負ける | FAIL |

基準 4 が本質的です。レースごとに計算した隊形確率が、「全レースに同じ周辺分布を答える」定数予測より悪い。つまり**レースごとに確率を出す意味がない**ということです。

### 4.2 原因: in_margin は事前情報でほぼ説明できない

`diagnose.py` が原因を切り分けています。決定的だったのは次の 1 行です。

```
corr(実測 in_margin, 予測 in_margin) = 0.197   →   R² = 0.039
```

推定 ST のレース内偏差から組んだ `in_margin` と実測 `in_margin` の相関は **0.197**、決定係数 **R² = 0.039**。`in_margin` の分散のうち事前に説明できるのは **3.9%** です。どんなサンプリング設計にしても、出力はほぼレース非依存の定数に潰れます。基準 4 で定数に負けたのは、この直接の帰結です。

レース単位の「散らばり」も予測できません。レース内 ST 散らばり(sd of dev)は平均 0.0428、変動係数 0.537 と大きく振れますが、A1 級の人数(corr −0.109)、風速(0.065)、波高(0.060)、場(−0.016)、同一場の直近 50 走平均(0.089)のどれとも相関しません。「今日は締まったスリットになりそう」を事前に言い当てる手がかりがないのです。

さらに、独立ノイズという構造自体が実測と合っていません。実測の `in_margin` は `|·| ≦ 0.6m` が 56.7% なのに対し、正規 σ = 0.048 では 37.2%、そのレースの実際の散らばりを先に知っているズルい設定(オラクル混合)でも 49.3% にしかなりません。芯の鋭さと裾の重さを同時に再現できない、と報告書は結論しています。

### 4.3 撤退ライン 1・2 も FAIL

`retreat.py` は隊形を 3 分類に粗くし、σ スケールを 0.60〜1.40 で全探索しました。周辺 ±3pt・Brier が定数未満・五分位校正 ±5pt の 3 指標を同時に満たすスケールは存在せず、校正が最良の scale 0.75 でも乖離 7.49pt(テスト窓では 8.0pt)でした。

| 「揃い」予測確率 | n | 予測 | 実際 |
| --- | ---: | ---: | ---: |
| 最下位五分位 | 1,562 | 0.374 | 0.438 |
| 最上位五分位 | 1,551 | 0.724 | **0.644** |

高確率側で一貫して過信しています。事後に確率を縮める再校正で数字は繕えますが、それは R² = 0.039 を隠すだけでレースごとの情報は増えないので採りません。撤退ライン 2(決まり手を落とす)は撤退 1 が前提なので、同時に不成立です。

### 4.4 撤退ライン 3(ST 帯)は PASS

隊形の確率は諦め、各艇の ST の**予測区間**だけを出す案を `band_calibration.py` で判定しました。テスト窓 47,000 艇走です。

**基準 A: 被覆率**。予測残差(実測 ST − 推定 ST)の sd は **0.0684 秒**、標準化残差の超過尖度 2.4 → Student-t(**df 9.14、scale 0.879**)を当てはめます。

| 名目 | 正規の実被覆 | 差 | Student-t の実被覆 | 差 |
| ---: | ---: | ---: | ---: | ---: |
| 50% | 53.5% | +3.5pt | **49.6%** | −0.4pt |
| 80% | 83.0% | +3.0pt | **80.7%** | +0.7pt |
| 95% | 95.6% | +0.6pt | **95.8%** | +0.8pt |

正規分布では 50% 区間の実被覆が 53.5% と過大(帯が広すぎる)なのに対し、Student-t では全水準 ±1pt 以内です。「被覆率」とは、名目 50% の区間に実測値が入った割合です。校正された区間なら 50% ちょうどになるはずで、超過は帯が広すぎる、不足は帯が狭すぎることを意味します。

なぜ裾が重い分布の方が 50% 区間は狭くなるのか、直感に反するかもしれません。同じ sd を持つ分布同士で比べると、裾が重い分布は確率質量を裾に回すぶん、芯が鋭くなります(§3.1 の分位表と同じ構造です)。50% 区間は芯の話なので、正規より狭くなるのです。

**基準 B: 選手別 σ に意味があるか**。選手別の ST 標準偏差を `K_SIGMA = 10` で収縮した相対倍率で帯幅を変えると、σ 五分位間の被覆ばらつきが **0.124 → 0.031** に縮みます。帯幅一定だと最安定型は 57.2%、最不安定型は 44.8% しか覆えず、「50% 区間」の意味が選手によって変わってしまいます。pinball loss は +0.21% と僅差ですが、この指標は帯幅の当否に鈍いため、被覆の一様性で判断しています。

**帯の幅**。p25〜p75 の幅は中央値 **0.082 秒 = 1.14m**(10-90 分位 0.070〜0.097 秒)。1 艇身 = 0.216 秒換算で**およそ 0.4 艇身**です。点で描くのとは明らかに見た目が変わり、「スリットは決め打ちできない」ことが図から伝わります。

### 4.5 凍結した定数と実装

Phase 0 が確定した定数は `scripts/boatrace/racer_st.py` にコードとして凍結されました。

```python
SIGMA_BASE = 0.0684   # 予測残差 (実測ST - 推定ST) の標準偏差
K_SIGMA = 10.0        # 選手別 σ を SD_PRIOR へ収縮するときの実効走数
SD_PRIOR = 0.0664     # 選手別 σ の事前分布 (全選手の実測 ST 標準偏差の平均)
Q75_K = 0.6173        # t.ppf(0.75, df=9.14) * 0.879。正規なら 0.6745
```

実装は当初計画の約 1/3 に縮み、新しいファイル種別(`data/estimate/slit_sim/`)や `build_slit_sim.py`、`TenkaiScenario.astro` は作られませんでした。既存の `racer_st` CSV に `N枠_推定ST_p25` / `N枠_推定ST_p75` の 2 列を足すだけです。ファイルを増やすと sparse-checkout・GCS ミラー・fetcher をすべて増やすことになり、得るものに対して割に合わないという判断です(第 11 章・第 13 章)。

第 18 章の状態ファイル `state.csv` には `重み付き二乗和` の列が 1 本追加されました。EWMA の平均が(重み付き和, 重み計)の 2 変数で表せるのと同じ理屈で、分散は二乗和をもう 1 本持てば `ws2/wt − (ws/wt)²` で得られます。全履歴を毎回走査せずに σ を持てるわけです。

```python:racer_st.py(抜粋)
def sigma_multiplier(self, regno: int) -> float:
    ws, ws2, wt = self.racers.get(regno, (0.0, 0.0, 0.0))
    if wt <= 1.0:
        return 1.0
    var = ws2 / wt - (ws / wt) ** 2
    sd = var**0.5 if var > 0.0 else SD_PRIOR
    shrunk = (wt * sd + K_SIGMA * SD_PRIOR) / (wt + K_SIGMA)
    return shrunk / SD_PRIOR

def estimate_band_for_racer(state: RacerStState, regno: int) -> float:
    """推定 ST の 25-75 パーセンタイル半幅 (秒)。コース依存は入れない。"""
    return Q75_K * SIGMA_BASE * state.sigma_multiplier(regno)
```

帯幅にコース依存を入れないのは、σ のコース差が 1C 0.048〜6C 0.053 と小さく、帯の見た目に効かないためです。旧 `state.csv`(二乗和なし)は倍率 1.0(帯幅一定)に退避して読めるようにし、リリース時に `build_racer_st.py --rebuild` を 1 回回して二乗和を作り直す運用にしています。

fun-site 側では `racer-st-schemas.ts` に `estimatedStP25` / `estimatedStP75`、`StartPredictionEntry` に `startTimingP25` / `startTimingP75`(いずれも optional で後方互換)を追加し、`prediction-builder.ts` の `startBandFor()` が「推定 ST 版で、かつ推定 ST 本体と帯の両方が揃う枠」にだけ帯を付けます(全国平均 ST にフォールバックした枠は帯なし。その枠だけ帯が広く/狭く見えるのを避けるため)。`StartPredictionDiagram.astro` は艇体の下に細いバーで舳先位置の予測区間を描き、凡例に「艇体下のバーは舳先位置の予測のブレ幅(25〜75 パーセンタイル)」と添えます(描画の詳細は第 15 章)。

ここで 1 つ、計画外の修正が必要になりました。帯を持つのは AI 推定 ST 版ですが、これを描画するのは `PredictorSpec.useEstimatedST` が true の予想者のカードに限られていました。その 3 者(v5_slit / v7_aggregate / v8_aionly)は 2026-08-10 までに全て退役しており、そのままでは**帯がどのカードにも出ない**のです。図は表示専用で回収率に効かないので予想者ごとに出し分ける理由がなく、レース詳細ページは予想者に依らず `startPredictionEstimated ?? startPrediction` を渡すように切り離しました。1 マーク距離 → 買い目の側は従来どおり `useEstimatedST` 駆動のまま、A/B の対象として残しています。

## 5. 再挑戦条件

ネガティブな結果を「やってみたが駄目だった」で終わらせると、半年後に別の人(あるいは自分)が同じ実験を繰り返します。設計書 `slit_sim_plan.md` §9.5 は、再挑戦の条件を数値で明文化しています。

> 隊形予想は「今のデータでは無理」であって「原理的に無理」ではない。新しい情報源(周回展示の行き足、部品交換情報、直前気象の細分化など)が取得できるようになった時点で `notebooks/slit_sim/diagnose.py` の `corr(実測 in_margin, 予測 in_margin)` を測り直し、**R² が 0.15 を超えたら**本命案を再検討する(現在 0.039)。

この 1 段落には、ネガティブ結果を資産にするための要素が揃っています。

- **どの量を測るか**: `in_margin` の R²。隊形確率が成立するかどうかを 1 つの数字に還元してある
- **どのスクリプトで測るか**: `diagnose.py`。リポジトリに残っているので、新しいデータを `st_panel.csv.gz` に入れて再実行すればよい
- **閾値**: 0.15。現在値 0.039 との距離が分かる
- **何が変われば測り直すか**: 新しい情報源の追加。モデルをいじるだけでは再挑戦にならないことが明示されている

同じ設計書には、やらない方がよいことも書かれています。展示 ST を予測 ST に混ぜる(相関 0.05、ノイズを足すだけ)、隊形パターンを離散カテゴリにして `component_keys` に足す(事前には隊形が決まらないので確率的にぼやけ、退役した v3_tenkai と同型の失敗になる)、ST 推定の精度改善を回収率目的で追う(§2.2 のとおり必要水準に届かない)、の 3 つです。

一方、§1 の条件付きテーブルは**レース後の振り返り**では即使えます。「1 コースが 1.2m 遅れたのに逃げた」は想定外の抵抗力の証拠ですし、買い目の外れ要因を「予想が悪かった」か「スリットが荒れた」かに分解できます。第 20 章・第 21 章の穴予想は、この「事後には強い」性質を決まり手の側から使う話です。

### 6.1 必要精度の逆算(§2.2 の再現)

真の ST に正規ノイズを乗せた疑似予測 ST でスリットを組み直し、1 コース 1 着の log loss の改善が「ノイズ 0 の上限」の何 % 残るかを測ります。元の検証は HistGradientBoosting を使っていますが、ここでは `in_margin` を 20 分位のビンに切って学習側の 1 着率をそのまま予測値に使う、最も素朴なモデルにしています。

```python:required_precision.py
"""必要精度の逆算: ST 予測の MAE と、スリット利得のうち回収できる割合の関係 (合成データ)."""
import numpy as np

V = 13.9                      # スタート艇速 m/s (ST 差 0.01 秒 ≒ 0.14 m)
rng = np.random.default_rng(0)
N = 60_000


def in_margin(st: np.ndarray) -> np.ndarray:
    """1 コースが 2〜6 コースの最先行艇より前に出ている量 (m)。正 = イン先手。"""
    lead = (st.mean(axis=1, keepdims=True) - st) * V
    return lead[:, 0] - lead[:, 1:].max(axis=1)


def logloss_gain(true_st: np.ndarray, win: np.ndarray, sigma: float) -> float:
    """真の ST に N(0, σ) を乗せた疑似予測 ST でスリットを組み直し、1 コース 1 着の
    log loss を測る。返り値はベースライン (事前確率のみ) からの改善幅。"""
    noisy = true_st + rng.normal(0.0, sigma, true_st.shape)
    m = in_margin(noisy)
    half = N // 2                                    # 前半で学習、後半で評価
    edges = np.quantile(m[:half], np.linspace(0, 1, 21)[1:-1])
    b_tr, b_te = np.digitize(m[:half], edges), np.digitize(m[half:], edges)
    rate = np.array([win[:half][b_tr == k].mean() for k in range(20)])   # ビン別 1 着率
    p = np.clip(rate[b_te], 1e-3, 1 - 1e-3)
    y = win[half:]
    ll = -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
    p0 = win[:half].mean()                           # ベースライン: 事前確率のみ
    ll0 = -np.mean(y * np.log(p0) + (1 - y) * np.log(1 - p0))
    return ll0 - ll


# --- 合成データ: レース内偏差は裾の重い Student-t、1 着率は in_margin の非対称な関数 ---
dev = rng.standard_t(df=6, size=(N, 6)) * 0.039      # slit_sim_plan §0.4 の形
true_st = 0.16 + dev
m_true = in_margin(true_st)
p_win = 0.73 / (1 + np.exp(-2.2 * (m_true + 0.9)))   # -1.2m 遅れで勝率半減、+0.6m で飽和
win = (rng.random(N) < p_win).astype(float)

gain_max = logloss_gain(true_st, win, 0.0)
print(f"実測 ST で組んだ場合の log loss 改善 (上限) = {gain_max:.4f}")
print(f"{'σ':>6} {'MAE':>6} {'利得率':>6}")
for sigma in [0.0, 0.01, 0.02, 0.03, 0.04, 0.06, 0.10]:
    mae = sigma * np.sqrt(2 / np.pi)                 # 正規ノイズの平均絶対値
    print(f"{sigma:6.3f} {mae:6.3f} {100 * logloss_gain(true_st, win, sigma) / gain_max:5.0f}%")
```

実行結果(合成データなので実測の表とは一致しません)。

```
実測 ST で組んだ場合の log loss 改善 (上限) = 0.1053
     σ    MAE    利得率
 0.000  0.000   100%
 0.010  0.008    94%
 0.020  0.016    78%
 0.030  0.024    60%
 0.040  0.032    48%
 0.060  0.048    29%
 0.100  0.080    12%
```

MAE と利得率の関係が §2.2 の表と同じ形(σ 0.02 = MAE 0.016 で 7 割台、MAE 0.05 前後で 3 割)になります。ポイントは `mae = sigma * sqrt(2/π)` の 1 行です。正規ノイズの平均絶対値は sd の約 0.8 倍なので、「MAE 0.016」は「予測誤差の sd 0.020」と読み替えられます。実測 ST のレース内 sd が 0.048〜0.070 なのですから、誤差 sd 0.020 という要求がどれほど厳しいか分かります。

### 6.2 帯の被覆率チェック(§4.4 の再現)

凍結した定数(`SIGMA_BASE`、`T_DF`、`T_SCALE`)で、正規と Student-t の 50 / 80 / 95% 区間がどれだけ名目どおりに実測を覆うかを数えます。

```python:band_coverage.py
"""ST 帯の被覆率チェック: 正規と Student-t で名目 50/80/95% がどれだけ守れるか (合成データ)."""
import numpy as np
from scipy import stats

SIGMA_BASE, T_DF, T_SCALE = 0.0684, 9.14, 0.879     # racer_st.py / report.md §4.4 の凍結値
rng = np.random.default_rng(1)
N = 50_000

# 合成データ: 選手ごとの σ 倍率 (0.7〜1.6) と、裾の重い残差 (超過尖度 > 0)
mult = rng.uniform(0.7, 1.6, N)
resid = rng.standard_t(df=T_DF, size=N) * T_SCALE * SIGMA_BASE * mult

print(f"{'名目':>4} {'正規':>7} {'Student-t':>10}")
for nominal in (0.50, 0.80, 0.95):
    q = 0.5 + nominal / 2
    k_norm = stats.norm.ppf(q)                          # 50% なら 0.6745
    k_t = stats.t.ppf(q, T_DF) * T_SCALE                # 50% なら 0.6173 (= Q75_K)
    cov = [float((np.abs(resid) <= k * SIGMA_BASE * mult).mean()) for k in (k_norm, k_t)]
    print(f"{nominal:4.0%} {cov[0]:7.1%} {cov[1]:10.1%}")

# 選手別 σ を無視して帯幅を一定にすると、安定型/不安定型で被覆が割れる
k = stats.t.ppf(0.75, T_DF) * T_SCALE
for name, sel in (("最安定 (倍率<0.9)", mult < 0.9), ("最不安定 (倍率>1.4)", mult > 1.4)):
    cov_var = (np.abs(resid[sel]) <= k * SIGMA_BASE * mult[sel]).mean()
    cov_const = (np.abs(resid[sel]) <= k * SIGMA_BASE).mean()
    print(f"{name}: 選手別σ {cov_var:.1%} / 帯幅一定 {cov_const:.1%}  (名目 50%)")
```

実行結果です。

```
  名目      正規  Student-t
 50%   53.8%      50.1%
 80%   82.3%      80.1%
 95%   94.9%      95.1%
最安定 (倍率<0.9): 選手別σ 49.7% / 帯幅一定 60.0%  (名目 50%)
最不安定 (倍率>1.4): 選手別σ 51.2% / 帯幅一定 35.6%  (名目 50%)
```

合成データの残差を t 分布から生成しているので Student-t が合うのは当然ですが、見てほしいのは 2 点です。1 つは、裾の重い残差に正規の係数を当てると 50% 区間が 53.8% と過大になり、その差が 95% 区間ではほぼ消えること(§4.4 の実測 +3.5pt / +0.6pt と同じ構造)。もう 1 つは、帯幅を一定にすると安定型 60% / 不安定型 36% と「50% 区間」の意味が選手で割れることです。実データではこれが 57% / 45%(§4.4 基準 B)でした。

本番の判定は `notebooks/slit_sim/band_calibration.py` が同じ計算を実測残差に対して行い、結果を `band_report.json` に出力します。

## 演習

`data/results/realtime/` の実測 ST から隊形を 3 分類(イン先手 / 揃い / イン遅れ、閾値 ±0.6m)し、1 コースの 1 着率が隊形でどれだけ動くかを集計してください。§1 の 6 分類が 3 分類でも再現できるか、また月ごとに割合が動くかを確かめる課題です。

```python:exercise_formation.py
"""演習: 実測 ST から隊形 3 分類を作り、1 コースの 1 着率を集計する (公開 CSV 1 か月分)."""
import sys

import numpy as np
import pandas as pd

V = 13.9
# 公開 CSV の URL。ローカルに落としてある場合はディレクトリを引数で渡す
BASE = (sys.argv[1] if len(sys.argv) > 1
        else "https://boatracecsv.github.io/data/results/realtime/2026/07") + "/{:02d}.csv"

frames = []
for day in range(1, 32):
    try:
        frames.append(pd.read_csv(BASE.format(day), dtype=str))
    except Exception:
        pass  # 開催なし・未収集の日
df = pd.concat(frames, ignore_index=True)

st = np.column_stack(
    [pd.to_numeric(df[f"{c}コース_スタートタイミング"], errors="coerce") for c in range(1, 7)]
)
ok = ~np.isnan(st).any(axis=1)               # 6 艇の ST が揃うレースだけ (欠測 '-' や 5 艇立ては除外)
st, df = st[ok], df[ok].reset_index(drop=True)

lead = (st.mean(axis=1, keepdims=True) - st) * V          # 平均 ST 基準の前出量 (m)
in_margin = lead[:, 0] - lead[:, 1:].max(axis=1)          # 1 コース − 外の最先行艇
formation = np.select([in_margin > 0.6, in_margin < -0.6], ["イン先手", "イン遅れ"], "揃い")
win1c = (df["1コース_艇番"] == df["1着_艇番"]).astype(float)

out = pd.DataFrame({"隊形": formation, "1C勝": win1c}).groupby("隊形")["1C勝"].agg(["size", "mean"])
out["占有"] = out["size"] / out["size"].sum()
print(f"レース数 {len(df)} (2026-07, 6 艇の ST が揃ったもの)  全体の 1C 1着率 {win1c.mean():.1%}")
print(out.reindex(["イン先手", "揃い", "イン遅れ"]).rename(columns={"size": "n", "mean": "1C 1着率"})
      .to_string(formatters={"1C 1着率": "{:.1%}".format, "占有": "{:.1%}".format}))
```
