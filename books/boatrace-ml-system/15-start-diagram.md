この章に出てくる判断はすべてその一点に帰着します。

## 1. スタート予想図

### 1.1 何を描くか

スタート予想図は、6 艇を**進入コース順**に上から並べ、各艇の**予測スタートタイミング(ST)**を横位置にした図です。
右が進行方向で、赤い縦線がスタートラインです。ST = 0 がスタートライン、ST が大きいほど遅い(左寄り)、
負値はフライング(スタートラインより右)になります。

![スタート予想図。6 レーンに艇色の艇が並び、舳先が予測 ST の位置にある。艇体の下に p25〜p75 の細いバー、右に ST 値と最速〜最遅の小さい数字](/images/boatrace-ml-system/15-start-prediction.png)
<!-- 図: boatrace-fun.net のレース詳細ページにある「スタート予想」のスクリーンショット。AI 推定 ST 版で、6 艇すべてに艇体下の帯(バー)と右カラム 2 段の ST ラベル(上: 予測 ST、下: 0.09〜0.19 のようなグレーの小字)が出ているレースを選ぶ。左カラムの艇番バッジと「Nコース」ラベル、赤いスタートライン、下の ST 目盛り(-0.10〜0.90)まで含めて切り取る -->

進入コースは直前情報の `previews/stt` から取り、まだ届いていない朝の時点では枠番をそのまま仮のコースにします
(第 3 章の daily / realtime の区別がここにも現れます)。予測 ST は AI 推定 ST(第 18 章の `racer_st`)で、
`racer_st` が無い日は選手の全国平均 ST にフォールバックします。どちらを使ったかは図の下の説明文に出ます。

一見すると単純な図ですが、「艇をどの大きさで描くか」「艇のどこを ST の位置に合わせるか」「横軸の範囲をどう取るか」の
3 つで見え方が大きく変わります。順に見ていきます。

### 1.2 1 艇身 = 0.135 秒の導出

この図の艇は、**1 艇身 = 0.135 秒**ぶんの長さで描きます。導出は次のとおりです。

- スリット(スタートライン)付近の艇速を 80 km/h と置くと、80,000 m ÷ 3,600 s = **22.22 m/s**
- ボートの艇長は約 3 m
- 3 m ÷ 22.22 m/s ≒ **0.135 秒**

つまり、2 艇の ST 差が 0.135 秒あれば、スタートラインを通過する瞬間にちょうど 1 艇身の前後差がついている、
という換算です。`start-diagram.ts` ではこれを定数 `BOAT_LENGTH_SEC = 0.135` として持ち、
艇の長さ(px)は `boatLengthPx(span, trackW) = (0.135 / span) × trackW` で軸レンジと水面幅から計算します。

:::message
**換算の違いについて。** 第 1 章では `slit_tenkai.md` §1 に従い、艇速 50 km/h(13.9 m/s)換算で
1 艇身 ≒ ST 差 0.216 秒と書きました。この章の図は 80 km/h 換算の 0.135 秒を使っています。
どちらも「艇長 3 m ÷ 艇速」の式は同じで、置いた艇速だけが違います(比は 1.6 倍)。
スリット通過時の実際の艇速はこのプロジェクトで計測していないので、どちらが正しいかは決められません。
解析側(第 19 章の帯幅の議論)は 0.216 秒、図の描画は 0.135 秒、と文書ごとに換算が固定されている、
と覚えておいてください。同じ「約 0.4 艇身」でも、どちらの換算かで意味する秒数が変わります。
:::

参考にした BOAT RACE 公式サイトのスタート情報図は、艇の画像が 54 px、目盛りが約 178 px/秒で、
換算すると 1 艇身 ≒ 0.30 秒になります。物理どおりの 0.135 秒に対して 2 倍以上長く描かれており、
図の上では実際より艇が重なって見えます。fun-site では見た目の派手さより「前後の重なりがそのまま艇身差として読める」ことを優先し、
物理どおりに合わせました。

### 1.3 舳先を ST の位置に置く

ST は「艇の**舳先**がスタートラインを通過した時刻」です。したがって艇を描くときは、
艇の中心や重心ではなく舳先を ST の x 座標に置き、そこから船尾を後方(左)へ 1 艇身ぶん伸ばします。

```
        ← 遅い                      速い →
  水面左端                    スタートライン(ST=0)
    |                                |
    |     [船尾======舳先>           |        ← ST 0.18 の艇
    |            [船尾======舳先>    |        ← ST 0.10 の艇
    |                                |
```

これは細かい話に見えますが、艇に長さを持たせた以上は避けられない決め事です。
中心を ST の位置に置くと、艇の長さを変えたときに舳先の位置がずれ、
「ST 0.10 の艇の舳先はスタートラインの 0.10 秒手前」という図の約束が崩れます。
舳先基準にしておけば、艇の長さは純粋に「重なり具合」の表現にだけ効きます。

`start-diagram.ts` のコメントには「円の中心ではなく舳先を値の位置に合わせる」とあり、
長さを持たない円で艇を描いていた段階があったと考えられます。艇に 1 艇身の長さを持たせた時点で、
舳先基準・艇番の位置・帯の位置がすべて見直しになりました(§2.4、§4)。

### 1.4 レンジは span 1.0 秒、目盛りは結果図と共有する

横軸の表示レンジは `ST_MIN = -0.1` から `ST_MAX = 0.9` の **1.0 秒**です。この幅にした理由は 2 つあります。

1. **実際に出る ST がクランプされずに収まる**。フライングは負値、出遅れ(L)は結果 CSV で 0.99 程度までの大きな値として記録されます
   (第 3 章の `results/realtime` の列仕様)。span 1.0 なら出遅れ判定の 1 秒手前まで入ります
2. **1 艇身が水面幅の 13.5% に収まる**。span を 0.5 にすると 1 艇身が 27% を占め、艇が大きすぎて重なりが読めなくなります

そして、この座標系はスタート予想図だけのものではありません。同じレースの確定結果を描く**スタート結果図**
(`StartResultDiagram.astro`)が、まったく同じレンジ・viewBox・レーン高・艇の大きさを使います。
定数はすべて `packages/web/src/lib/start-diagram.ts` の 1 箇所にあり、2 つのコンポーネントはそれを import するだけです。

![スタート結果図。予想図と同じ目盛りで、実測 ST の位置に艇が並ぶ。フライングの艇は赤縁で ST ラベルが赤い F.02 表記](/images/boatrace-ml-system/15-start-result.png)
<!-- 図: 同じレースの「レース結果」セクションにある「スタート(進入順)」のスクリーンショット。できればフライング艇が 1 艇いるレース(赤縁の艇 + 赤い F.0X ラベル)を選び、予想図と横軸の目盛りが同じ位置にあることが分かるよう、目盛り行まで含めて切り取る -->

「予想と結果を同じ目盛りで見比べられる」ことがこの 2 図の目的なので、
**実測値に合わせてレンジを可変にすることは意図的にやりません**。
レンジを毎回データに合わせると、予想図で 0.15 だった位置が結果図では別の位置に描かれ、比較ができなくなります。
レンジ外の値が出た場合は、舳先だけを水面内(`clampBowX`: 左端 +12 px 〜 右端)に留め、
正確な値は右カラムの数値ラベルに必ず出します。クランプが起きた回だけ図の説明文に
「表示レンジ(-0.10〜0.90 秒)を外れた艇は端で止めています」と一文を足します。

結果図にはもう 2 つ、予想図には無い扱いがあります。

- **フライング**: 艇を赤縁(stroke 2.5)にし、ST ラベルは負号ではなく `F.03` の形にします(出走表の今節成績と同じ書き方)
- **ST が取れなかった艇**(欠場・エンストで CSV が空欄 → 0): 位置が決まらないので水面に艇を出さず、
  左の艇番バッジと右の `—` だけを出します。0 のまま描くとスタートラインぴったりに並んでしまい、
  最速スタートに見えるためです

### 1.5 全国平均 ST の 0.00 は 0.25 に補完する

全国平均 ST が `0.00` の選手は「公表実績なし」(新人・長期離脱明けなど)であって、最速スタートではありません
(第 1 章 §3.2)。図でも 0.00 のまま描くと舳先がスタートラインに張り付き、実績のない艇が最も速く見えてしまいます。

そこで、共有パッケージの `effectiveAvgST()` が 0.00 と未定義を `NO_RECORD_ST_FALLBACK = 0.25` に置き換えます。
この定数はスタート予想図の描画と、1 マーク走行距離の計算(§3)の**両方**が同じものを参照します。
片方だけ補完すると、図では遅く描かれているのに買い目では速い扱い、という食い違いが起きるためです。
補完値 0.25 の検討経緯は第 18 章(H6: 欠損を級別事前分布で補完)にあります。
この補完を入れただけで ST 推定の MAE が 0.0033 改善したことも同章で触れます。

## 2. 予測区間の帯

### 2.1 点推定 1 本では先頭コースを約 7 割外す

予測 ST が 6 艇ぶん揃えば、それを並べて「スリット隊形」を 1 本描けます。
しかし、その隊形はどのくらい当たるのでしょうか。boatracecsv 側の検証記録に数字があります。

| 予測 ST の元 | スリット順位の Spearman | 先頭コースの一致率 | 出典 |
| --- | ---: | ---: | --- |
| スタート展示 ST | 0.082 | 21.2% | `slit_tenkai.md` §5.1 |
| 全国平均 ST | 0.244 | 28.9% | 同上 |
| 全国平均 ST(B0、テスト窓) | 0.231 | 24.1% | `phase2_report.md` |
| AI 推定 ST(M3、テスト窓) | 0.296 | 34.2% | 同上 |

テスト窓は 2026-06-21〜07-20 の daily フレーム、n = 28,201 艇走 / 4,609 レースです。
先頭艇一致のチャンスレート(当てずっぽう)は 1/6 ≒ 16.7% なので、どの予測 ST もチャンスよりは良いものの、
最も良い AI 推定 ST でも先頭コースを当てられるのは 3 分の 1 で、**66〜76% は外します**。
これが骨格で「約 7 割外す」と書いた根拠です。

つまり、予測 ST を点で 6 つ並べて 1 本のスリットを描くことは、
「このレースは 4 コースが先手を取る」と 3 回に 2 回は間違う断定を図で行っているのと同じです。
第 19 章で扱うとおり、実測 ST の隊形は結果を強く規定する(強さpt に足して log-loss −0.143)のに、
締切前の情報からは組めない、というのがこの問題の構造です。
図としてできることは、断定をやめて**どこまで当てにならないかを見せる**ことです。

### 2.2 「隊形の確率」は出せず、帯だけに縮退した

最初の計画(`slit_sim_plan.md`)は、推定 ST に選手別の分散を持たせてモンテカルロでサンプリングし、
「ほぼ揃い 57% / イン遅れ 24% / イン先手 19%」のように**隊形の確率**を出すものでした。
校正が取れなければ実装しない、と決めて Phase 0 の検証を先に行った結果、2026-08-10 に本命案は不合格になりました。
1 コースの前後量 `in_margin` の分散のうち事前情報で説明できるのは 3.9%(相関 0.197)しかなく、
どうサンプリングしても出力がレース非依存の定数に潰れ、隊形の Brier スコアが定数予測に負けたためです。

計画にはあらかじめ 3 段の撤退ラインが書かれており、1(隊形 3 分類)と 2(決まり手を落とす)も不成立、
**撤退ライン 3「確率をやめ、ST の p25〜p75 帯の描画だけ実装する」**だけが合格しました。
検証の中身と設計書の書き方は第 19 章に譲り、ここでは帯の中身と描画だけを扱います。

### 2.3 帯の中身: Student-t で校正した p25〜p75

帯は `racer_st` CSV の `N枠_推定ST_p25` / `N枠_推定ST_p75` の 2 列で、推定 ST を中心に対称です。
半幅は次の式です(`racer_st.py`)。

```
半幅 = Q75_K(0.6173) × SIGMA_BASE(0.0684) × 選手別 σ 倍率
```

- `SIGMA_BASE = 0.0684` 秒は予測残差(実測 ST − 推定 ST)の標準偏差
- `Q75_K = 0.6173` は **Student-t(df 9.14、scale 0.879)** の 75 パーセンタイル係数です。
  残差は超過尖度 2.4 と裾が重く、正規分布の係数(0.6745)を使うと 50% 帯の実被覆が 53.5% と 3.5pt 過大になります。
  t 分布にすると名目 50 / 80 / 95% に対して実被覆 49.6 / 80.7 / 95.8%(テスト窓 47,000 艇走)で、全水準 ±1pt 以内に収まります
- 選手別 σ 倍率は、選手の実測 ST のばらつきを `K_SIGMA = 10` で全体平均(`SD_PRIOR = 0.0664`)へ収縮した相対値で、
  実データで 0.68〜1.61、中央値 0.98 です。ST のばらつきは選手の持ち味として実在し(前半 / 後半の split-half 相関 0.555)、
  帯幅を一定にすると安定した選手は 57%、不安定な選手は 45% しか覆えず、区間の意味が選手で変わってしまいます。
  倍率を入れると σ 五分位間の被覆のばらつきが 0.124 → 0.031 に揃います

帯の全幅は中央値 **0.082 秒**(10〜90 分位 0.070〜0.097 秒)です。
解析側の 50 km/h 換算では 1.14 m ≒ 0.4 艇身、この図の 0.135 秒換算で描くと 0.082 / 0.135 ≒ 0.6 艇身に相当します。
点で描くのとは明らかに見た目が変わり、「スリットは決め打ちできない」ことが図から伝わる幅です。

なお、帯幅は進入コースにほとんど依存しません(σ のコース差は 1 コース 0.048〜6 コース 0.053)。
そのため `racer_st` は枠番ベースの日次 1 本で足り、直前情報で進入コースが変わっても帯を計算し直しません。

### 2.4 帯の描き方

帯を図に載せるときの判断は 3 つです。

**艇体の下に細いバーで出す。** `slit_sim_plan.md` §9.3 の実装当初は「艇の背後に艇色 opacity 0.22 の帯」でした。
その後 §1.3 のとおり艇が 1 艇身の長さを持つようになり、背後に敷いた帯は艇に隠れて見えなくなりました。
現在は艇体の下(`cy + BOAT_HEIGHT_PX / 2 + 3`)に高さ 5 px の角丸バーとして描きます。
バーの左端が `stToX(p75)`(遅い側)、右端が `stToX(p25)`(速い側)で、**舳先がどこに来るか**のブレ幅を表します。

**数値も併記する。** 右カラムの ST ラベルは 2 段で、上段が予測 ST、下段がグレーの小字で `0.09〜0.19` のように最速(p25)〜最遅(p75)の順に出します。
帯が無い艇(全国平均 ST にフォールバックした枠)は下段を出しません。バッチ側の `startBandFor()` は
「AI 推定 ST 版で、かつ推定 ST 本体と p25 / p75 の両方が揃っている枠」にだけ帯を付けます。
一部の枠だけ帯が無い状態は起こり得ますが、フォールバック値に架空の帯を付けるよりは正直です。

**予想者に依らず帯つき版を出す。** 元々、AI 推定 ST 版のスタート予想図(`startPredictionEstimated`)は
`PredictorSpec.useEstimatedST` が true の予想者のカードにだけ表示されていました。
ところが該当する 3 者(v5_slit / v7_aggregate / v8_aionly)は 2026-08-10 までに全員退役し、
そのままでは**帯がどのカードにも出ない**状態になりました。
図は表示専用で買い目にも回収率にも効かないので、予想者ごとに出し分ける理由がありません。
レース詳細ページは予想者に関係なく `prediction.startPredictionEstimated ?? prediction.startPrediction` を渡すように変え、
帯を持つ AI 推定 ST 版に統一しました。

```ts:race/[date]/[stadiumId]/[raceNumber].astro(抜粋)
// 1マーク距離 (= 買い目 = 回収率) の予測 ST を AI 推定 ST にするかは
// 予想者ごとの useEstimatedST で決める。ここは A/B の対象なので触らない。
const usesEstimatedST = spec?.useEstimatedST === true;
// スタート予想図は **予想者に依らず** AI 推定 ST 版 (startPredictionEstimated)
// を使う。racer_st が無い日は共通図 (全国平均 ST) にフォールバック。
const startPrediction = prediction.startPredictionEstimated ?? prediction.startPrediction;
```

一方で、1 マーク走行距離(= 買い目 = 回収率)側の予測 ST を決める `oneMarkDistanceOptionsFor()` は**触っていません**。
こちらは A/B 実験の対象なので、従来どおり `useEstimatedST` 駆動のままです。
「図は自由に良くしてよいが、買い目に効く経路は実験の設計を壊さない」という線引きが、この差に現れています。

図の説明文には「艇体下のバーは舳先位置の予測のブレ幅(25〜75 パーセンタイル)で、実際の ST が約半分の確率でこの範囲に入ります」と書いてあります。
§2.3 の被覆率 49.6% を、そのまま日本語にしたものです。

## 3. 1 マーク予想図

### 3.1 横軸は ST と同じ「秒」の次元

1 マーク予想図は、スタート後に各艇が 1 マーク(最初のターンマーク)へどれだけ進んでいるかを描く図です。
横軸は **1 マーク走行距離**で、共有パッケージの `computeOneMarkDistances()` が計算します。

```
distance = (1 − 予測ST) + 強さpt / 50 − 1.6
```

予測 ST は既定で全国平均 ST(0.00 は 0.25 補完)、`useEstimatedST` な予想者だけ AI 推定 ST です。
強さpt は第 7 章の総合評価で、この式は「ST が 0.01 秒速い」と「強さpt が 0.5 高い」を等価に扱っています
(50 pt = 1 秒の換算)。この距離が買い目の選定基準(基準艇 ±0.10 の窓)になっており、
強さpt ±5.0 pt の窓と等価スケールになる話は第 8 章で扱います。

ここで重要なのは、この式の第 1 項が ST(秒)で、残りの項も同じ秒の次元に揃えてある点です。
横軸が秒なら、スタート図と同じ **0.135 秒 = 1 艇身** の換算がそのまま使えます。
1 マーク予想図は `start-diagram.ts` の `boatLengthPx(DIST_SPAN, TRACK_W)` と艇の輪郭パスをそのまま呼び、
自前の軸レンジと水面幅を渡すだけで、スタート図と同じ形・同じ換算の艇を描いています。

### 3.2 進行方向が逆なので鏡像の艇を使う

この図では距離が大きいほど**左**に描きます(基準線が右端寄りにあり、艇は 1 マークへ向かって左へ進む)。
スタート図と進行方向が逆なので、艇の輪郭も鏡像にします。

`start-diagram.ts` の内部関数 `hullPath(bowX, cy, len, dir)` は `dir = 1` で舳先が右、`dir = −1` で舳先が左の艇を返し、
公開関数の `boatHullPath` / `boatHullPathLeft`、`boatCanopyX` / `boatCanopyXLeft`、`clampBowXIn` / `clampBowXInLeft` は
それぞれ `dir` の符号が違うだけです。形は完全に同一で、船尾が伸びる向きと、舳先をクランプする側だけが逆になります。
右向きの図では ST が遅い艇ほど船尾が水面**左端**をはみ出し、左向きの図では距離が小さい艇ほど船尾が水面**右端**をはみ出します。

### 3.3 軸 span 1.0 と下限 −0.1 の理由

1 マーク予想図の軸レンジは `DIST_MIN = -0.1` から `DIST_MAX = 0.9` で、スタート図と同じ span 1.0 です。
以前は span 0.5 でしたが、艇に 1 艇身の長さを持たせた時点で問題が出ました。
span 0.5 だと 1 艇身が水面幅の 27% を占め、進行距離が 0.365 を超える艇、つまり**上位艇ほど**船尾が水面の外に出てしまいます。
span 1.0 なら 13.5% で収まり、スタート図と艇の見え方も揃います。

下限を 0 ではなく −0.1 にしたのは、基準線(distance = 0)を水面の右端そのものに置かないためです。
下限 0 だと、進行距離が 0 付近や負の最下位艇は右端にクランプされ、舳先しか見えずに右で見切れていました。
基準線の右に 0.1 ぶん(水面幅の 10%)の余白を取ることで、遅れている艇も 1 艇身まるごと描けます。
span は 1.0 のままなので、艇身と水面幅の比は変わりません。

レーンの並びは 5・3・6・1・4・2 で固定です(距離順に並べ替えません)。並びを固定しているのは、
レース内で艇の位置が変わっても同じ艇番が同じ行に居続けるようにするためだと考えられますが、
設計文書に理由は記録されていません。

## 4. 描画の細部に理由を残す

図の実装には、コードを読んだだけでは「なぜそうしたのか」が分からない判断がいくつもあります。
fun-site ではそれを `docs/web.md` のコンポーネント表と、コードのコメントに残しています。
主なものを挙げます。

**艇番は艇体ではなく左カラムのバッジに出す。** 艇が 1 艇身の長さを持つので、ST が遅い艇ほど船尾が水面左端をはみ出します。
艇体に番号を乗せると、その艇の番号だけ読めなくなります。参照した公式サイトのスタート情報図も、艇番は水面の外に別カラムで出しています。
`LEFT_PAD = 86` はこのバッジ(20 px 角)と「N コース」ラベルのぶんです。

**はみ出しは `clipPath` ではなく地色のカーテン矩形で隠す。** SVG の `clipPath` は `id` で参照する仕組みで、
同じページに同じ図が複数並ぶ(予想者のカードごとにスタート図と 1 マーク図が出ます)と `id` が衝突し、
別のインスタンスの `clipPath` を参照してしまいます。fun-site では艇を描いた後に、
水面の左右へ図の地色(`FIGURE_BG`)と同じ色の矩形を被せることで、はみ出した船尾を隠しています。
描画順は「地色 → 水面 → レーン線 → 艇と帯 → カーテン → スタートライン → 目盛り → バッジとラベル」です。

**スタートラインは艇の後に描く。** 先に描くと艇に隠れて見えなくなります。カーテンの後、ラベルの前です。

**1 号艇だけ枠線を付ける。** 1 号艇の艇色は白で、水面の淡い青に溶けるので、グレーの縁(`#94a3b8`)を付けます。
他の艇は艇色と同じ色の縁です。艇色は公式の 6 色(白・黒・赤・青・黄・緑)で、共有パッケージの `BOAT_COLORS` から引きます(第 14 章)。

**舳先のテーパーは艇幅程度に抑える。** 艇は 1 艇身ぶんの長さがあり縦横比が細長いので、
舳先のテーパーを長く取ると矢印に見えます。`hullPath` は肩の位置を `min(len × 0.3, BOAT_HEIGHT_PX)` に留めて舳先を立てています。

**カーテンの上に描くラベルは正確な値を必ず出す。** 舳先をクランプする以上、図の位置は真の値と食い違うことがあります。
右カラムの数値は常に真の値で、クランプが起きた回だけ説明文に断りを足します(§1.4)。

こうした判断は 1 つ 1 つは小さく、後から見ると「なぜ `clipPath` を使わないのか」「なぜ艇番が艇の上にないのか」と
リファクタリングしたくなるものばかりです。理由を残しておかないと、次に触る人(半年後の自分を含みます)が
同じ落とし穴に戻ります。fun-site の `docs/web.md` が 1 コンポーネントに数百字の「なぜ」を書いているのはそのためです。

## 5. 簡略版コード(TypeScript)

実装から本質だけを抜いた形です。ST の配列から、舳先基準・1 艇身換算の x 座標と、帯の矩形を返します。
`hullPath` の `dir` を −1 にすれば 1 マーク予想図用の鏡像になります。

```ts:start-diagram-lite.ts
/** 表示レンジ(秒)。負値側がフライング。span 1.0 で出遅れ判定の 1 秒手前まで入る */
export const ST_MIN = -0.1;
export const ST_MAX = 0.9;
export const ST_SPAN = ST_MAX - ST_MIN;

/** 水面の x 範囲(viewBox 600 px、左に艇番バッジ 86 px、右に ST ラベル 80 px) */
export const TRACK_LEFT = 86;
export const TRACK_RIGHT = 600 - 80;
export const TRACK_W = TRACK_RIGHT - TRACK_LEFT;

/** 1 艇身ぶんの時間(秒)。艇速 80 km/h = 22.22 m/s で艇長 3 m を通過する時間 */
export const BOAT_LENGTH_SEC = 3 / (80_000 / 3_600); // ≒ 0.135
export const BOAT_HEIGHT_PX = 26;

/** ST → x。ST=0 がスタートライン、大きいほど左(後方)、負値は右(フライング) */
export const stToX = (st: number): number => {
  const clamped = Math.min(Math.max(st, ST_MIN), ST_MAX);
  return TRACK_RIGHT - ((clamped - ST_MIN) / ST_SPAN) * TRACK_W;
};

/** 軸レンジ span・水面幅 trackW の図における 1 艇身の px。1 マーク図も同じ式 */
export const boatLengthPx = (span: number, trackW: number): number =>
  (BOAT_LENGTH_SEC / span) * trackW;

/** レンジ外でも舳先だけは水面に残す。船尾のはみ出しはカーテン矩形で隠す */
export const clampBowX = (x: number): number =>
  Math.min(Math.max(x, TRACK_LEFT + 12), TRACK_RIGHT);

/** 真上から見た艇。舳先 (bowX, cy) から船尾が dir の逆へ len 伸びる。dir=-1 で鏡像 */
export const hullPath = (bowX: number, cy: number, len: number, dir: 1 | -1): string => {
  const half = BOAT_HEIGHT_PX / 2;
  const sternX = bowX - dir * len;
  const shoulderX = bowX - dir * Math.min(len * 0.3, BOAT_HEIGHT_PX); // テーパーは艇幅程度
  return `M ${bowX} ${cy} L ${shoulderX} ${cy - half} L ${sternX} ${cy - half} L ${sternX} ${cy + half} L ${shoulderX} ${cy + half} Z`;
};

export type StartEntry = {
  readonly boatNumber: number;
  readonly courseNumber: number;
  readonly startTiming: number;
  readonly startTimingP25?: number; // AI 推定 ST 版のみ
  readonly startTimingP75?: number;
};

export type BoatLayout = {
  readonly boatNumber: number;
  readonly cy: number;
  readonly bowX: number;
  readonly hull: string;
  /** 舳先位置の p25〜p75。無い艇は null */
  readonly band: { readonly x: number; readonly width: number } | null;
};

/** 進入コース順に並べ、舳先を ST の位置に置いた艇と帯の座標を返す */
export const layoutStartDiagram = (
  entries: readonly StartEntry[],
  topPad = 24,
  laneHeight = 50,
): readonly BoatLayout[] => {
  const len = boatLengthPx(ST_SPAN, TRACK_W);
  return [...entries]
    .sort((a, b) => a.courseNumber - b.courseNumber)
    .map((e, i) => {
      const cy = topPad + i * laneHeight + laneHeight / 2;
      const bowX = clampBowX(stToX(e.startTiming));
      const band =
        e.startTimingP25 != null && e.startTimingP75 != null
          ? { x: stToX(e.startTimingP75), width: Math.max(stToX(e.startTimingP25) - stToX(e.startTimingP75), 2) }
          : null;
      return { boatNumber: e.boatNumber, cy, bowX, hull: hullPath(bowX, cy, len, 1), band };
    });
};
```

`layoutStartDiagram` の戻り値をそのまま `<path d={hull}>` と `<rect x={band.x} width={band.width}>` に流し込み、
その後にカーテン矩形・スタートライン・ラベルを描けば、§1〜§2 の図になります。
実装ではここに加えて、コックピットの楕円、艇番バッジ、2 段の ST ラベル、目盛り、説明文の出し分けがあります。
